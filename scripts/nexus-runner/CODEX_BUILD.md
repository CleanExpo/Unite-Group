# Opt-in contained Codex build worker

`build-codex.mjs` is a Windows-only, one-task alternative to the existing Claude
build executor. Importing it does nothing. It does not change the shared broker,
register a host, change the database, consume another queued task, publish a PR,
merge, deploy, charge a customer, or automatically restart a handoff.

The model edits a plain, selected text snapshot. The controller uses existing
Codex ChatGPT authentication by reference; the tool policy must deny access to
that authentication. No runner bearer or GitHub/provider keys enter the child
environment. A Job Object provides cleanup; the separately measured explicit
MXC permissions provide the access boundary. Neither prompts nor code review
establish that boundary.

## Prerequisites

Before any application claim, the worker requires all of these:

- Native Windows, the pinned existing Codex and Node 24 executable bytes, and
  the unchanged `research-containment.ps1` broker.
- An existing registered runner and its application bearer, available only to
  the parent controller. `NEXUS_APP_URL` is an HTTPS origin and `RUNNER_ID` is
  explicit. The worker never registers or acquires credentials.
- An operator-created immutable profile and qualification packet, each supplied
  with its raw SHA256. The complete narrowly named Q1 edit/TypeScript/Vitest matrix and actual
  model-tool Q2 must qualify this worker source hash and exact profile. The old
  broad fullQ1Pass:false report is preserved; it is not relabelled. Partial native probes cannot enable it.
- A local canonical Unite-Group origin with the explicitly pinned commit at
  `refs/remotes/origin/main`. The worker never fetches or selects a moving base.
- Explicit selected text input paths and narrower allowed edit paths. An empty
  private ledger directory must not already exist; its parent must exist outside
  the repository. Keep it outside all model-readable roots.

Run with existing Node 24, passing explicit values:

```text
node scripts/nexus-runner/build-codex.mjs --once --task-id UUID
  --repo ABSOLUTE_CANONICAL_CHECKOUT --base FULL_MAIN_SHA
  --input-path apps/web/src/FEATURE --input-path package.json
  --allowed-path apps/web/src/FEATURE --ledger ABSOLUTE_NEW_PRIVATE_LEDGER
  --profile ABSOLUTE_PROFILE_JSON --profile-sha RAW_SHA256
  --qualification ABSOLUTE_QUALIFICATION_JSON --qualification-sha RAW_SHA256
```

The selected inputs must include the source, existing lockfiles/configuration
and project instructions needed for this approved change. Selecting a directory
containing tracked credentials or unsupported entries refuses extraction. The
worker validates the entire Git inventory before selecting inputs, copies blobs
without tar extraction, rejects non-text/oversized inputs and credential/control
paths, and rejects symlinks, junctions, hardlinks and Windows path aliases.
Preexisting hardlink aliases are rejected; MXC is not claimed to deny reading a
preexisting alias. Deletions are intentionally unsupported in this first worker.

## Exact profile

The JSON profile has `schema: "contained-codex-profile/1"`,
`stageContract: "isolated-edit-ts-vitest/1"`, and absolute native
`codexExecutable`, `nodeExecutable`, `gitExecutable`, `powershellExecutable`,
existing `codexHome`, `readonlyRoots`, `environmentKeys`, `timeoutMs` (1–1800000),
`outputBytes` (1024–1048576), `toolInventory`, and `argvTemplate`.

`argvTemplate` includes `exec`, `--ignore-user-config`, `--ignore-rules`,
`--ephemeral`, `--strict-config`, `--json`, `--skip-git-repo-check`, `-C`, the
literal `${snapshot}`, and a final `-` for stdin. Required repeated `-c` values:

```text
windows.sandbox="mxc"
forced_login_method="chatgpt"
default_permissions="contained_codex_build"
permissions.contained_codex_build.filesystem={":root"="deny",":minimal"="read",":workspace_roots"={"."="write"},"C:/nvm/nvm/v24.14.1"="read"}
permissions.contained_codex_build.network.enabled=false
features.code_mode_host=true
agents.enabled=false
agents.max_concurrent_threads_per_session=1
```

The filesystem string is derived exactly from `readonlyRoots` in its recorded
order; it cannot add unrecorded paths. Required config also includes `approval_policy="never"`,
`shell_environment_policy.inherit="none"`, `web_search="disabled"`, and an exact
`shell_environment_policy.set` generated by exported
`shellEnvironmentConfiguration(profile, environment)`. The generated set includes
only the bounded OS allowlist and rebuilt PATH from `childEnvironment`, with no
CODEX_HOME, trace settings or provider/runner credentials. It is compared against
the actual invocation environment before claim. Minimum threads 1 is the installed
CLI's accepted value; `agents.enabled=false` removes collaboration. Zero was an
actual rejected configuration and is not presented as a spawn guard.
`--disable` must list each of: `apps`, `browser_use`, `browser_use_external`,
`browser_use_full_cdp_access`, `computer_use`, `hooks`, `in_app_browser`,
`multi_agent`, `plugins`, `remote_plugin`, `view_image`, `skill_search`, and
`skill_mcp_dependency_install`, `image_generation`, `goals`, and `sleep_tool`. Unsupported settings fail without fallback.
Actual Q2 must prove the resulting inventory and configuration, including
non-loading of injected user/project integrations.

The finite facade inventory is exact: top-level `functions.exec`,
`functions.wait`, `functions.request_user_input`, and
`functions.request_user_input_async`. The exec facade declares exactly seven
nested helpers: `apply_patch`, `exec_command`, `list_mcp_resource_templates`,
`list_mcp_resources`, `read_mcp_resource`, `write_stdin`, and `clock__curr_time`.
The profile's `toolInventory` equals exported `FACADE_INVENTORY`, and its
`toolCatalogSha256` binds the actual complete first-inference tool definitions.
Code-mode host and command-runner sibling executable bytes are independently
pinned in addition to native Codex/Node/broker. An old flat shell inventory or
unexpected collaboration/connector/helper refuses qualification.

Q2 measures facade control/wait and absence of Node/filesystem/network globals;
`exec_command` and `write_stdin` require control/read/write/network measurements;
`apply_patch` requires control/read/write measurements. UI question helpers and
the clock have explicit schema-only non-I/O treatment; no pointless question is
asked for coverage. MCP listing must actually be empty and unknown-server reads
must actually refuse during Q2. Production generation rejects all MCP tool-call
events and asks the model to avoid MCP/UI calls; no blanket MCP allowlist exists.
The escalation refusal requirement needs genuine independent proof; a forbidden
live test that was not called never counts as executed. Any separately approved
actual offline handler regression must be labelled accurately.

Environment keys are restricted to the source's OS allowlist. PATH is rebuilt
from Node/Windows directories; CODEX_HOME references existing controller auth.
Provider API/Git/Node startup keys are excluded. Physical read-only roots must
have canonical paths without reparse ancestors and be disjoint from controller
auth, the real checkout/Git common directory and private ledger.

## Qualification custody

`contained-codex-qualification/1` packets contain `profileHash` (canonical JSON
SHA256), `stageContract: "isolated-edit-ts-vitest/1"`,
`excludedCapabilities: ["package_install","package_manager","next_build"]`,
`workerSha256`, `publicationHelperSha256`, `brokerSha256`, `codexSha256`, `nodeSha256`, `codeModeHostSha256`, `commandRunnerSha256`, exact
`toolInventory`, `inferenceRequest: {path, sha256, pointer}`, and `checks`.
The inference pointer selects the genuine raw first request with its `tools`
array; namespace/signatures and the full catalogue hash are verified. Each check has `stage`, `name`, `expected`,
`evidence: {path, sha256}`, and an RFC6901 `pointer` into that actual raw JSON.
Evidence files must be ordinary single-link files. Referenced measurements must
equal the fixed expected values; a report's PASS label cannot substitute.

Q1 names requiring `true`: `workspace_control`, `outside_read_denied`,
`outside_write_denied`, `network_denied`, `auth_denied`, `git_denied`,
`escape_denied`, `local_ipc_denied`, `breakaway_denied`,
`app_graph_typescript`, and `app_relevant_vitest`. The last two require the
actual application dependency graph and relevant existing real application
tests with retained input/source/test/runtime identities and actual exits;
synthetic TypeScript/Vitest controls alone do not qualify them.
`descendant_cleanup` and `broker_death_cleanup` require measured `0` active
descendants. Q2 requires `controller_success`, `finite_inventory`, `config_injection_denied`,
`facade_globals_absent`, `facade_control`, `facade_wait_control`,
`mcp_resources_empty`, `mcp_templates_empty`, `mcp_unknown_refused`,
`ui_clock_schema_only`, `collaboration_absent`, `host_job_membership`, and
`exec_command.escalation_refused`. Host I/O checks additionally use `TOOL.control`
and `TOOL.CAPABILITY_denied` for the capability matrix above. All Q2 measured
values must be true; missing coverage refuses startup. Failed V1-V4 probes remain
failed evidence and do not qualify this protocol.

The operator is responsible for retaining genuine native executions and any
lossless parsed-output custody transforms, not inventing packet values. This
format verifies custody and required measurements; it is not an independent
attestation authority or a substitute for the actual native qualification.
Worker/profile/binary/policy/tool changes invalidate the corresponding packet.
The offline unit fixtures are explicitly synthetic and grant no eligibility.

## Sealed handoff and operator stage

The initial exact claim must return a current approved software delivery bound
to accepted intent, signed approval, execution assignment and the same runner.
Every later check sends `resumeOnly: true`; it cannot claim queued work. The
original authoritative `claimed_at` and assignment `acceptedAt` are sealed and
compared verbatim. A later same-runner attempt cannot adopt an earlier seal.

The controller launches the unchanged broker using bounded JSON stdin, native
argv and a minimal environment. Only a successful broker exit with a complete,
bounded, parseable model stream permits enumeration. Nonzero exits, timeouts,
unknown executable tools, uncertain cleanup, out-of-scope changes, aliases or
changed real Git metadata refuse sealing. The worker derives actual file hashes
and a full output Git tree using a private index/object store; unselected base
files remain part of that tree. The original index, hooks and object metadata
must remain unchanged during the model stage.

The measured installed executable bytes are streamed separately with a 512 MiB
limit; an existing installed runtime hardlink is permitted only for that pinned
measurement. Snapshot and custody files still require a single link. Existing
`~/.claude/HARD_STOP` prevents calls and is watched during the model stage.
Controller exit zero does not assert passing tests: completed command exit codes
and file-change failure statuses are retained, while test verification remains
`requires_operator_verification` for the separate deliberate operator stage.

Success writes immutable `claim.json`, `execution.json`, and `seal.json`, then
stops at **awaiting_operator_verification**. The app task remains running under
its original claimant. Final prose, a matching patch or an existing PR is not a
release receipt. No PR #1190 adoption is supported.

An authorised operator reviews and independently audits this exact sealed output,
then runs `--once --accept-candidate` with the same configuration and an explicit
hash-pinned `--acceptance` request before importing into the trusted pipeline.
That request has schema `contained-codex-operator-trust/1` and the same seal,
run, tree, branch, authority, original timestamps, acceptedAt, trustExecutableCode
and independentAudit fields described below. The candidate audit JSON binds
`output_tree`, `seal_sha256`, `verdict: "PASS"`, `implementation_agent: "codex"`,
a distinct `reviewer_agent`, and empty `blocking_findings`.

The accept-candidate stage checks the actual unchanged snapshot and current
read-only original claim, then records immutable `operator-acceptance.json` and
returns its SHA256. It does not import, publish or invoke hooks. This makes the
pre-pipeline trust decision durable separately from later native/PR evidence. Review is
a trust decision. Normal hooks execute only after that decision, with existing
operator credentials, never inside this worker's model stage. The operator uses
the generated unique branch and exact base/output tree. After explicit
pre-hook trust, full ordinary package-manager, full build, full repository
gauntlet, keeper and native gates must pass on the actual candidate SHA before
push and a new canonical draft PR. Required hosted CI and fresh independent
review then pass on that pushed SHA before explicit finalizer release. Hosted
CI is required after the triggering push; it is not a circular pre-push gate.
Narrow model-stage Q1/Q2 never replaces these normal checks. No automatic import,
hook execution, push or PR creation is implemented here.

The final acceptance JSON has `schema: "contained-codex-operator-acceptance/1"`,
`sealSha256`, `runId`, `branch`, `outputTree`, `authorityHash`, both original
`claimedAt` and `assignmentAcceptedAt`, `trustExecutableCode: true`, `acceptedAt`,
`headSha`, `baseSha`, `operatorAcceptanceSha256` from that prior recorded trust,
`independentAudit: {path, sha256, verdict: "PASS"}`,
`nativeReceipt: {path, sha256, headSha}`,
`postCiReview: {path, sha256, ciSnapshotHash, execution?: {path, sha256}}`, and
`nativeVerification: {path, sha256, headSha, receiptSha256}`. Its timestamp records
the initial deliberate trust decision; do not silently accept altered code.
The normal verifier's retained actual execution-result JSON contains
`mode: "verify"`, `exitCode: 0`, `headSha`, `receiptSha256`, `verifierSha256`,
`stdoutSha256`, `stderrSha256`, `stdoutPath`, `stderrPath`, and
`commandArtifact: {path, sha256}`. That pinned actual command JSON contains
`mode: "verify"`, `headSha`, `receiptSha256`, and the original `argv` including
`verify`. It is a custody wrapper around the existing
canonical verifier, not a replacement verifier or an unauthenticated PASS label.

Only an explicit operator invocation can finalize:

```text
node scripts/nexus-runner/build-codex.mjs --once --finalize
  [the same task/repo/base/inputs/allowed-paths/ledger/profile/qualification flags]
  --acceptance ABSOLUTE_ACCEPTANCE_JSON --acceptance-sha RAW_SHA256
  --gh ABSOLUTE_EXISTING_GH_EXE
  --publication-python ABSOLUTE_EXISTING_PYTHON_EXE --publication-python-sha RAW_SHA256
  --publication-module ABSOLUTE_MAINTAINED_PR_RELEASE_GATE_PY
  --pr https://github.com/CleanExpo/Unite-Group/pull/NUMBER
```

This stage uses the operator's existing GH CLI only for fixed read-only PR and
current policy/check queries. The adjacent publication helper hashes the existing
Python executable before/after and imports the pinned unchanged maintained
`pr_release_gate.py` with isolated, no-bytecode flags. It calls only
`publication_environment`, `publication_policy`, `publication_checks`,
`publication_prerequisites`, and `published_status`; it never calls publish or
attest. The full bounded canonical pagination and check-app binding are reused.
It verifies a newly created open draft on the generated
branch, canonical repo/main, actual full tree and direct base parent, current
exact-task original claim, receipt/review/native-verifier custody, and the
canonical `nexus/release-receipt` status. Status alone does not authenticate the
native receipt. After the awaited same-attempt claim check, it repeats live PR,
base/head/draft identity, policy and check/status readback and rejects drift.
The original native receipt-bound independent review remains unchanged; a
separate post-CI supplement must bind the same head/base, current CI snapshot,
and a review time after actual required CI completion. The pinned supplement
itself must contain `ci_snapshot_hash`, or the separately pinned actual collector
execution JSON must use schema `contained-codex-post-ci-execution/1`,
`headSha`, `baseSha`, `ciSnapshotHash`, `reportSha256`, `startedAt`, and
`completedAt`, bound to the genuine retained execution after current CI.
Acceptance metadata alone cannot attach an old report. The last PR identity
query follows the final publication bridge immediately before local receipt
writes and the release call, rejecting changes during that bridge. Native issue/original
review timestamps precede new PR creation. There is no publication command.

A rebase, operator amendment or changed tree/base is rejected. Superseding seals
are not generated by this first implementation; such recovery requires an
explicit separately reviewed implementation and renewed qualification, never
editing the old seal or borrowing its acceptance. Finalization writes a durable
release-request before one release call. An ambiguous response is retained for
operator readback; restarting cannot replay it. A verified `awaiting_approval`
delivery build is an **awaiting-review handoff**, not product Done, production
launch, onboarding or payment evidence.
