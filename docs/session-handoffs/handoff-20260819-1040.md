**Root cause found (the substantive finding).**
`apps/web/supabase/migrations/20260620010000_auth_signup_allowlist.sql` ends each
auth hook with `REVOKE EXECUTE … FROM PUBLIC`. That revoke removes only the
**implicit** PUBLIC grant and leaves an **explicit** `anon=X` / `authenticated=X`
entry in `proacl` untouched — and this project's `pg_default_acl` re-grants to
anon and authenticated on every new object. A migration that reads as though it
locked the JWT-minting hook shipped a surface that is still anon-callable.
**Revoking from PUBLIC is not revoking from anon.**
