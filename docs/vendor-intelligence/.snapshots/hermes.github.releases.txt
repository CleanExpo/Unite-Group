Hermes Agent v0.22.2
Release Date: October 15, 2026
v0.22.1 was built from the wrong commit. It shipped unreleased gateway work, and the Microsoft Store app could stick on "Connecting." 0.22.2 is the release 0.22.1 was meant to be.
Known issue: Sessions that ran under the 0.22.1 gateway can't be deleted in 0.22.2.
Highlights
The gateway starts after a reboot again. After a restart, Linux can hand an early PID to an unrelated process, and the gateway could mistake it for a running gateway, so a supervised gateway (systemd, launchd, Docker) refused to start. Hermes now records the boot it started in, and when it can't tell, it asks the host lock, which only a live gateway holds. ( #138594 , fixes #133744 )
Long local-model turns survive on laptops. Local requests always stream with prompt-reading progress (shown in the status line), stall timers skip time the machine was asleep, a recovered local server gets another try instead of a breaker that failed every later message, and compression no longer times out while the server is still reading a long conversation. On Windows unified-memory machines, model launch and the prompt cache are sized to free memory. ( #138560 )
Below is everything in the 0.22 release line since v0.22.0: the fixes 0.22.1 was meant to ship, plus the two above. Work that is only on main ships with v0.23.0.

Hermes Agent v0.22.0
Release Date: October 13, 2026
Since v0.21.0: ~24,200 commits · ~6,080 merged PRs · ~15,600 files changed · ~2,045,000 insertions · ~1,140,000 deletions · ~7,180 issues closed · ~2,520 contributors
The Threshold Release. Hermes was the god of thresholds: the doorway, the crossing, the boundary stone. v0.21.0 assembled the pantheon; v0.22.0 is about getting through the door. A fresh desktop install now opens on a guided setup chat that runs on a free trial model, so a newcomer is talking to Hermes before they own an API key. Connectors carry the agent across into the apps you already use, with no account needed to start. Local models bring it home to your own hardware with a one-click llama.cpp runtime. And the threshold itself got sturdier: tested SemVer stable releases that installs follow by default, signed desktop packages (including the Microsoft Store), and one package manager underneath everything. Around that spine: a 600-plugin catalog, the Claude 5.5 / GPT-6 model wave, password-manager sign-in for the browser, a bot screen you can take over, one backend and one gateway for every profile, and a codebase a third smaller. This is the largest window Hermes has shipped, about 2.5x the v0.21.0 cycle, and it rolls up and fully documents the v0.21.1–v0.21.7 patch releases.
✨ Highlights
A first launch that sets itself up — Open the desktop app on a computer where you have never used Hermes and it starts a short setup chat instead of a settings screen. One card at a time it asks your name, an accent color and a layout, which apps to connect, which plugins to install, then gives a quick tour and offers up to four first tasks picked for you. It runs on a free trial model ( nous/welcome , once per OS user), so it needs no key; Skip setup ends it and Settings → Run onboarding again brings it back. The agent also gained set_theme , so "make it violet, dark mode" works in any desktop chat. ( #137429 , #137522 , #137807 , #134209 , #105258 — @alt-glitch , @OutThisLife , @ethernet8023 , @rewbs )
Connectors: Hermes works inside your apps — The agent can now act in hosted apps such as Linear and Notion through the Nous tool gateway: ask for an app, sign in once in your browser, and the tools are usable in the same turn. You do not need a Nous account to start; the first time you use an app, Hermes creates a free connectors-only identity. The desktop has a new Connectors page that puts hosted apps and your MCP servers in one list (it replaces the MCP tab), the same setup card appears in the TUI and CLI, and you can connect several named accounts of one app (a work and a home account) and manage them with /connectors or hermes connectors . ( #106842 , #111008 , #119074 , #135143 , #135072 , #135097 , #135151 , #135173 , #137426 — @alt-glitch , @rewbs )
Local models in one click — Hermes can now run open models entirely on your machine with nothing leaving it: no account, no API key. It installs and maintains llama.cpp with the right engine for your hardware (CPU, CUDA, Metal, Vulkan or ROCm), rates every catalog model against your GPU and RAM, and picks the highest-quality build that fits. Downloads pause and resume, the server starts and stops with Hermes, and engine updates are one click. Start from Settings → Providers → Local Models on Windows, macOS and Linux, or hermes model → Local models in a terminal. The catalog includes Qwen3.8 27B, Qwen3.8 Flash Next (with its MTP speculative head), Qwen3.6 35B-A3B and DeepSeek V4 Flash, plus any GGUF from Hugging Face. ( #100667 , #101823 , #128768 , #111423 , #133111 , #134116 — @jquesnelle , @ethernet8023 )
Stable release channels — Hermes now ships tested SemVer releases. Every release passes source CI, Docker, Nix, signed desktop builds and install/upgrade runs on every OS before it is published, and source installs now move from release to release by default instead of tracking every commit on main . Prefer the bleeding edge? hermes update --set-channel main , or the new channel switch in Desktop Settings → About . Moving to an older release is labelled a rollback and never happens without asking, and installer reruns keep you on the channel you chose. ( #102765 , #135847 , #135949 , #136313 , #137780 — @ethernet8023 , @KoNit-K )
Signed desktop packages, the Microsoft Store, and one package manager — The desktop app is now a sealed, signed package that carries its own Python and Node and updates itself, so first launch builds nothing. Windows gets a signed MSIX (x64 and ARM64) through App Installer or the Microsoft Store; macOS gets a signed, notarized build for Apple Silicon. Underneath, a new unified package manager ( hermes pm ) owns every pinned, hash-checked tool and Python environment: updates build a new environment and switch only once it passes its check, so a failed or killed update can no longer leave you half-applied. ( #102765 , #132361 , #132386 , #120339 , #122221 — @ethernet8023 )
The Plugin Catalog: 600 reviewed plugins — The plugin catalog launched this cycle and grew to 600 entries, each pinned to a reviewed commit and installable from Hermes Desktop or the CLI. Browse by category and star ranking with a page per plugin and per author; catalog rules keep listed plugins from patching Hermes internals or shipping unscannable binaries. Memory providers now live with their makers (Honcho, Supermemory, Hindsight, Mem0, OpenViking, Holographic), as do Home Assistant, Spotify and Langfuse: existing users are migrated automatically, and the default install got leaner. ( #69446 , #111415 , #117808 , #113381 , #114732 , #131267 , #132476 , #136436 — @itpartypattaya , @happy5318 , and 400+ plugin authors)
The Claude 5.5 and GPT-6 model wave — Claude Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5, GPT-6 Astra, Sol and Luna plus GPT-6.1 Sol, and Gemini 4 Argon are pickable on Nous Portal, OpenRouter and native routes where offered. Prior reasoning is now replayed by default on every provider that can read it, across resume, branches and compaction, so long multi-step work keeps its train of thought. And when a provider has a bad hour, Hermes waits out transient 503/529/timeouts in visible, bounded cycles instead of ending your turn. ( #100577 , #119304 , #126842 , #134759 , #128248 , #137955 , #136358 , #116353 — @kshitijk4poor , @unsupportedpastels , @100yenadmin , @mssteuer , @xxxigm )
Sign in to websites with your password manager — The browser agent can log into sites with logins from 1Password, Bitwarden or Hermes's own encrypted vault, and the model never sees the password. If nothing is saved, you get a masked prompt in the CLI, TUI or Desktop to save it, one-time codes are filled without entering the conversation, and card and address fills at checkout need your confirmation. ( #106480 , #107585 , #137084 )

Hermes Agent v0.21.7
Release Date: October 11, 2026
Patch release. This tag rolls up the ~204 PRs merged since v0.21.6 into a stable release for the desktop app (macOS Apple silicon, Windows), the Microsoft Store and MSIX, the installer, Docker and Hermes Cloud. Full curated notes for this window ship with v0.22.0.
What this patch ships for source installs ( hermes update and the desktop app's updater on a git checkout):
Updates now follow tagged releases. A source install of the official repository updates to the latest published vX.Y.Z release instead of every commit on main . An install already newer than the latest release stays where it is and waits for the next one; nothing is moved back. To keep following every commit: hermes update --set-channel main . Forks and mirrors keep following main . Store, MSIX and bundled desktop installs are unchanged.
Choose the channel in the desktop app. Settings ▸ About ▸ Updates has an Update channel switch (Stable releases / Every commit) for source installs, and the update dialog now shows which channel you are on.
Reasoning survives resume. Signed thinking replays after hermes chat --resume and on the next gateway turn, and Bedrock Converse reasoning models no longer get rejected on resumed sessions.
Updates no longer fail behind some firewalls. Installs on main no longer fetch a release record that regional firewalls could answer with 403. The stable check uses your GitHub token when one is set ( GITHUB_TOKEN or gh auth login ) and reports a GitHub rate limit as a rate limit.
About this release
Measured at commit 1fd18277267152893a8a24792b79213e7ca3f899 , the window since v0.21.6 contains 740 non-merge commits across 4,156 changed files (+86,775 / −26,980), 204 merged PRs and 69 closed issues .
Also in the window, undocumented here on purpose: plugins running built-in Desktop app actions ( ctx.runAction ) and a plugin SDK pet bubble ( ctx.pet.say ); core-made Codex requests so plugins never hold the token; skills installed mid-session reaching the model without a prompt rebuild; Krea 2 Medium Turbo as the default image lane for new paid subscribers, with a FAL fallback when managed Krea refuses a request; faster desktop updates (the React Compiler pass cached by content, the compiled renderer reused when only the install stamp changed, unchanged native inputs left in place); pinned installs that check out only the pin; compaction marks emitted to Relay; and new community plugins including memory-shield, command-ledger, Memoria, Model Router, wyoming-voice-bridge, codex-account-switch and redline.
Full curated release notes for this window ship with v0.22.0 , which will document everything from v0.21.0 onward — highlights, feature areas, and complete contributor credits. Nothing in this window is skipped.
Updating
Desktop app: updates itself. Microsoft Store installs update through the Store.
CLI: hermes update , or re-run the installer one-liner.
Docker / Hermes Cloud: nousresearch/hermes-agent:stable (or :latest ).

Security Fixes
Dashboard authentication hardening
Spoofed X-Forwarded-For headers could reset the password-login rate limit and get around the per-IP cap on native sign-in ( #133367 )
Unauthenticated login requests could write unbounded values to the auth audit log ( #133369 )
The public /auth/ routes had no request-body size limit ( #133370 )
Native sign-in could send login codes to a non-loopback redirect, which allowed session takeover ( #130685 )
Thanks to Tenable Research for reporting all four issues (TRA-725, TRA-726, TRA-727, TRA-728). The native sign-in redirect issue was also reported independently and fixed by @Froraut . The X-Forwarded-For fix builds on community work by @Hinotoi-agent and @BearHuddleston ( #40285 ).
Repository git filter hardening
Automatic git calls (session workspace snapshot, subagent worktrees, kanban, worktree cleanup, hermes -w ) could run clean / smudge / process filter programs defined by an untrusted repository's own config, before the first prompt ( #130661 )
Thanks to 燕涛 for reporting this privately. It was also reported and fixed publicly by @jonpol01 ( #126017 , #126019 ) and @JoaoMarcos44 ( #126075 ).
Email gateway sender hardening
A quoted display name in the From header (e.g. "Victim <victim@example.com>" <attacker@evil.test> ) could make an attacker's message pass the email allowlist as an allowed sender ( #125212 )
Thanks to Daniel Steele ( @keeltrace ) for reporting this and writing the fix ( #124322 ).

Patch release. This tag rolls up the ~338 PRs merged since v0.21.2 into a stable tagged release for downstream consumers (Docker images, Hermes Cloud, hosted deployments). It exists so the remote-gateway sign-in fixes below reach Cloud agents, which auto-update to the newest release tag.
What this patch ships for remote Desktop / Cloud users
Remote dashboard sessions no longer expire on refresh bursts ( #110061 , fixes #55712 ; salvage #71548 @Doud-FR , #55717 @liuhao1024 ). Both refresh paths on the gateway (cookie gate and the desktop's native bearer route) now coalesce concurrent requests carrying the same rotating refresh token, so a Desktop wake burst can no longer replay an already-rotated token into the Portal's reuse detection and revoke the whole session. Refresh also runs off the event loop, so a slow identity provider no longer freezes /api/status . Pairs with Portal-side NousResearch/hermes-portal#1209 (sliding 30-day idle horizon, 5-minute rotated-token grace).

Hermes Agent v0.21.2 (v2026.9.11) — The state.db Patch Release
Release Date: September 11, 2026
Patch release. v0.21.0 shipped a large rewrite of the session store's connection handling, and for some installs it made state.db fragile: second writers cancelling each other's locks, healthy databases reported as corrupt, one bad row killing sessions list . This release closes that class and rolls up everything else that landed on main in the four days since v0.21.1.
About this release
Measured at commit 04dd80a977f40b05e5b2054111747af07a61886a , the window since v0.21.1 contains 947 non-merge commits across 1,869 changed files (+182,504 / −15,564) and 312 merged PRs . 140 contributors appear in commits, co-author trailers, or salvage credits.
✨ Highlights
state.db reliability campaign (six PRs, 44 issues closed)
If your state.db broke after 0.21.0, this is the release for you. Six PRs fix the root causes rather than the symptoms:
No more second writers. Profile gateways wrote hosted-room state into the root state.db every 5 seconds; the dashboard opened a writable handle on startup; cron's lifecycle guard did a raw open() on a live database (which cancels the gateway's POSIX locks — the classic "how to corrupt SQLite" recipe); doctor --fix would checkpoint under a live holder. All four are gone: hosted rooms live in shared-state.db , the dashboard opens read-only first, the guard goes through the tracked connection registry, and doctor --fix refuses a checkpoint it can't prove is safe. ( #108076 — salvage #103489 @RikETS , #102682 @JoaoMarcos44 , #108012 @Halldrix , #105428 @TaoMasterCoder )
Healthy WAL databases stop wedging. OpenZFS (deleted) dentries and a close() racing an append_message both produced a sticky DeletedWalGenerationError on a perfectly good store; the read pool was handed out under an unconfirmed journal mode; a transient disk I/O error on WSL2 killed get_session on the first attempt; and a "state.db locked" banner was broadcast after the lock had already cleared. ( #108082 — salvage #107411 @chelsealong , #105578 @ca-shrimp , #105711 @gaoanze888 , #106958 @nikkoxgonzales ; co-authored @QDung210 , @fangliquanflq , @Sahilvishnaliya )
FTS damage no longer kills your turn. An error scoped to the full-text-search index was classified as whole-file corruption and fail-closed the conversation. It's now fts_index : search degrades, the index rebuilds later, the transcript store is untouched. Same PR: doctor names structural damage honestly instead of "FTS write corruption", the FTS write probe catches the stale-index shape that passed every check while every write failed, .recover output no longer fails startup on orphan FTS5 shadow tables, header-zeroed databases recover instead of being refused, and the dashboard analytics poller returns a 503 instead of 520K tracebacks a day. ( #108130 — salvage #97843 @SulthanZahran1 + #97841 @Finn763 , #88604 #56824 #103657 @liuhao1024 , #106890 @nftpoetrist , #103321 @jangomango76 , #91413 @leegunwoo98 , #102808 @TaoMasterCoder )
One corrupt row no longer kills sessions list , export, or insights. A TEXT timestamp or a 1e30 epoch used to crash the whole listing; malformed marker JSON crashed json_extract ; more than 999 ids crashed bulk delete/prune. One coerce_epoch() helper on every reader (bad rows render ? with a WARNING naming the session), a json_valid guard, IN-list chunking, and batched export hydration. ( #108086 — salvage #106071 @Xipong , #101726 @efe-arv , #94701 @liuhao1024 , #102679 @mssteuer , #100658 @Mi55ed )
Sessions never bind to or read another profile's database. The Desktop launch backend could pin itself to the wrong profile's state.db under a HERMES_HOME override race; session_search by bare ID silently scanned every profile and returned someone else's transcript; recovery guidance pointed at the wrong file; profile delete kept a handle open (WinError 32). ( #108074 — salvage #102534 @HexLab98 , #106975 @Sora-bluesky )
Opening state.db no longer takes the write lock when nothing needs writing. A one-shot hermes process opening the store behind a busy gateway stalled 4–20 s and then failed with "database is locked". Now 0.01 s. ( #108067 — salvage #106751 @kshitijk4poor , #101881 @jonpol01 )
Also in the window from the same subsystem: a fresh state.db no longer publishes FTS tables before owning the rebuild lock ( #106311 ), a handle that lost its WAL generation no longer checkpoints stale frames at shutdown ( #106315 , #106840 ), a clobbered first page is quarantined with its WAL instead of opened destructively ( #106587 ), WAL setup leaves an unverifiable database untouched ( #106568 ), and quarantined handles refuse VACUUM/FTS optimize ( #106343 , #106349 ). Most of these salvaged community diagnoses by @kshitijk4poor .
Multi-profile isolation hardening
A cluster of fixes for installs running several profiles under one gateway (multiplex): secondary-profile bots no longer inherit the default profile's allow-lists ( #107616 ), adapters no longer send credentials to the default profile's host ( #107617 ), stdio MCP servers no longer receive the default profile's vault secrets ( #107630 ), MEDIA: delivery can no longer attach another profile's .env / auth.json / state.db ( #107609 ), Feishu drive callbacks and /p/<profile>/ webhook replies stay on the routed profile ( #107620 , #107626 ), and secondary profiles no longer get a sibling's Nous bearer from per-process memos ( #107611 ).
Desktop backend spawn storms are over
Bot Mode used to spawn or dial one backend per profile on launch and on every roster tick, hovering the Bots roster spawned a backend per row, and profile switches could spawn a duplicate primary. ( #108069 , #108107 , #108118 , #108134 , #107969 , #108112 — salvage #102512 , #103634 , #103399 , #107997 and others by @kshitijk4poor )
Password-blind credential vault
The agent can now sign in, pay, and fill addresses from 1Password, Bitwarden, or the local Hermes vault without ever seeing a secret; two-factor codes come from a saved authenticator key or are asked for in the user's UI ( #106480 , #107585 ). Private git plugins install with the user's stored credentials ( #106981 ).
Plugin catalog and one Plugins page
A curated, SHA-pinned plugin index with CLI, admission CI, docs and dashboard ( #69446 ); Desktop gets one Plugins page owning agent + desktop plugins, install, catalog and per-commit pinning ( #107212 , #107314 , #107321 ); Radio ships as an opt-in SDK plugin ( #107072 ).
Nous free tier and guided first launch
Free inference and connectors out of the box with one command to sign in ( #105258 , #105260 ), /login from a chat ( #105261 ), connector tools (Gmail, Linear, Notion, ...) searchable through tool_search ( #106842 ), and a guided first launch behind HERMES_GUEST_ONBOARDING=1 ( #107697 , #107958 , #107985 , #108211 ).
